# 云端调试与 Sites 工作教训

记录日期：2026-10-08（Asia/Shanghai）。来源是本任务中的用户反馈、实际工具结果
及操作记录。这里只记录能确认的错误和检查缺口；未知原因保留为未知，不补写推测。
不保存任何账号、密码、令牌或设备私人画面。

## 已发生的问题与防止复发的要求

| 问题 | 已确认的事实与今后的要求 |
| --- | --- |
| 没有及时把帮助文档地址与发布地址区分清楚 | `learn.chatgpt.com` 是官方文档。实际 Site URL 只能来自成功部署结果，不能拼接或猜测。 |
| 对环境发布和 Sites 发布的说明不够清晰 | 云环境发布保留配置和文件，不能证明网站已创建。逐项报告：运行实例、配置草稿、已发布环境版本、Sites 保存版本、Sites 已部署、远程 E2E。 |
| 发布能力缺口发现后，沟通和交接不够直接 | 起步检查可调用的 Sites 工具、项目绑定和后端入口；若缺失尽早明确。用户已多次选择 Sites，不要重复要求同一动作，不把用户已授权误写成待授权。 |
| 交付了用户无法打开的云端文件链接 | `SITES.md` 在云端存在且可读，但客户端报“无法打开文件”。环境启动状态可能相关，具体根因未确认。不能断言文件丢失、权限错误或启动就是根因。检查实际文件并区分客户端结果；打开工具返回 `queued` 不等于成功。关键结果必须在答复正文可读。 |
| 初始页面在用户预览中没有样式 | 预览 HTML 不能保证 CSS/JS 相对资源被加载。已将样式内嵌；正式交付仍检查部署页面的 CSS、脚本、CSP、控制台错误和实际截图，不能只检查文件生成成功。 |
| 截图验证未覆盖用户要求的即时操作体验 | 单次 PNG 只能诊断。实时验收必须连续解码 H.264，并通过 WebSocket 控制真实设备，再观察视频中的反馈。当前实现为 scrcpy + WebCodecs。 |
| 本机跨域结果容易被误读成公网 Sites 已通过 | 两个 loopback origin 的浏览器测试已通过，但不能证明公网 TLS、WSS、Sites 权限和 CSP。CORS 不提供网络入口，浏览器也不能直接使用云后端的 localhost。 |
| 性能目标与实际性能需要更明确区分 | 配置上限 15 fps，不是实测。已有样本约 408×720、2 fps；宿主无 KVM，软件虚拟化和软件编码有限制，不承诺手机模拟器流畅度。 |
| 网络结论曾未及时按运行层和配置变化更新 | APK 下载、宿主 HTTPS 代理、客体 DNS、Android DNS、原生 IM TCP 都须分开检查。发布后重试相关操作；以前的 403 不能沿用为当前结果，代理 HTTPS 200 也不能证明 IM 登录可用。 |
| 网页滚动后沿用旧画布位置，输入焦点错误 | 私有登录调试时，滚动使点击坐标失效，敏感输入误入可见账号框。已修正为先滚动画布进入视口，再取实际边界；输入秘密前必须确认 Android 密码字段获得焦点，失败立即停止。已清理临时截图，不在记忆中保存输入内容。 |
| 软键盘出现后沿用旧 Android 坐标 | 键盘改变布局后，旧登录按钮坐标落在键盘区域。每次键盘/方向/布局变化后重新观察画面；不要盲点或重复提交。不能把 Android 返回键一律当成“隐藏键盘”，它也可能退出登录页。 |
| 输入清理最初不够可靠 | 追加字符不能代替替换。实时控制已增加全选和删除；需要替换时先确认字段、清空，再输入。秘密值通过不回显输入传递，不放入 shell 参数、脚本或通用日志。 |
| 静止画面曾被视频读超时误判 | scrcpy 静止时可能不发送新帧。已去掉无帧头的固定超时，连接存活用 WebSocket 心跳和 socket 状态判断；保留有界帧体读取、发送和清理。 |
| 重复检查、过长输出增加等待与误判风险 | 已通过且无相关改动的测试不反复跑；只重验变化影响的链路。批量读取要控制输出，不能把被截断当作已读完整。用户登录/操作期间不并行运行会导航设备的 E2E。 |
| 状态表述可能超出证据 | 进程存在、APK 前台、输入完成、“登录中”均不代表登录成功。最终页面、认证结果和业务收发分开报告；未知不能写成通过。 |

## 下一次接手时的执行要求

1. 读取当前环境版本、文件、工具和进程状态；历史记录只作为线索。环境发布后
   进程与会话可能失效，按 README 恢复，不重建数据。
2. 复用已有前端，检查 Sites 支持的构建产物，再实际保存版本并部署。只使用平台
   返回的项目 ID、版本 ID 和 URL，不制造 `.openai/hosting.json` 的关联标识。
3. 取得可用的 HTTPS/WSS 后端入口，准确配置 `QTRADE_SITE_ORIGIN`、
   `QTRADE_API_ORIGIN` 与凭据文件；HTTP 和 WS 均验证来源及鉴权。
4. 从实际 Site URL 检查：页面资源、授权访问、API 状态、视频连续解码、点击和
   拖动反馈、停止/重连及后端离线状态。用户能打开页面与设备控制成功分别验收。
5. 提交登录前确认当前 UI 和密码焦点；登录未成功就明确报告，不能推断密码错误。
   业务发送只在用户明确指定测试对象和内容后执行。
6. 交付真实 URL、这次已完成的验证和未完成项。若当前会话缺少发布工具，说明
   能力限制并提供可复用的具体交接，不声称已经发布，不让用户重复之前的配置。
