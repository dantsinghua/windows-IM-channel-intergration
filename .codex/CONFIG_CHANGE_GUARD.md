# 配置变更保护机制

安琳，本机制用于采集端及相关配置修改，承接 2026-10-20 R6-114。当前用户要求与更具体项目规范优先。它不增加全局 hook、额外 CLI 模型或重复授权流程。

## 修改前必须建立的对照

先核 cwd、分支、HEAD、dirty、最新交接与在途任务；精确备份将改文件的原字节、SHA256 和换行。把用户原要求、现行基线、实际行为逐项列成矩阵，记录「保留 / 修改 / 既有缺口 / 本轮未验」；未请求的功能不得删除、隐藏或缩小为实现方清单。冲突先登记原句和证据，错误解读由助手承担，不能写成用户反复改变需求。

| 必查场景 | 对照与验收要求 |
|---|---|
| 地址与认证 | 空白机器可输入 URL 和两钥；地址可编辑；区分格式、认证、保存和运行应用，秘密不回显 |
| 工作台身份 | 显示名与稳定 ID 分离；可信已有 ID 保留，无才生成；改名不换 ID |
| 多采集端与账号 | 两个采集端、两个账号的身份/目录差异与授权可见性独立核验；不从单绑定伪造发现池 |
| 目录 | 本地候选预览与线上协议分开；slot 增删不改变其他 slot 路径；预览不代表对端已发现 |
| 邮件中转 | radio、表单、保存、收发与指定路由逐项核对；既有 SMTP/选路缺口单列，不能把入站认证当双向完成 |
| 持久化与运行 | 本地配置所有权、Vault、首次只读 seed、保存后不覆盖/回退、待对齐状态分别核验 |
| 安全与旧状态 | owner/账号/工作台授权、CAS、identity、UNKNOWN/journal、登录态和用户 dirty 保留；禁止清理或绕过 |
| 文案 | 正式源码和现行规格扫描禁词；按语义改为文件网关、邮件账号、邮件地址或邮件服务器；技术锚点例外登记 |

## 所有权与对端快照

修改前冻结 peer schema、提交号、相关源码 hash、读取时点和配置所有权；只读源不是授权写入源。禁止把对端 repository、运行配置或当前 host 绑定冒充采集端自己的配置仓库。共享配置只能在明确合同内首次只读 seed；本地保存后不回退覆盖。

对端相关 schema/hash 变化即停止跨端对齐，重新比对差异与所有权，不覆盖对端并行改动。若对端未具备发现、选择、名称或多采集端合同，先完成用户已要求的本地修正，准确标待对齐；不自动发明/发布新协议、重绑或切链路。本轮对端已有选择/通讯录持久化交付，早期无发现接口快照不得当当前事实；旧认证缓存 `stale=true` 与 `seq20199 UNKNOWN` 仍需单列。采集端新目录未发布，真实 `3007378246 → 415011447` 联合验收等待安琳继续指令，不因读取新报告扩大业务动作。

## 独立验证与报告

实现、开发者测试、独立验收、文档与只读终审分别负责。独立测试以用户原要求和基线构造，不只接受实现方缩小后的清单；至少覆盖正常配置、更换地址、改名不换 ID、多个账号、错误归属与旧状态保护。质量门受阻者不修改或绕过该门。

认证、目录预览、发现、选择、发送、回执分别报告来源、版本、命令与结果；没有本轮证据就写未验。历史点对点 PASS、包构建成功、旧通过数字或对象已构造都不证明本轮业务恢复。报告明确区分本地静态检查、合成执行、真实环境验收和未验证项。

正式产品文案禁用「公网信箱」「信箱」及泛称「邮箱」。例外仅限第三方真实定位字符串/协议字面值、技术标识（如 `ossbox`、`mailbox`）、API 路径、Vault refs 以及不改写的历史原始证据；例外不能扩张为当前 UI 文案。文案修订不改变邮件功能或协议语义。

规格修改后必须在 `docs/` 执行带超时的 `python3 check-truth-tables.py` 并得到 exit 0，不改旧门消除冲突；新增规则先由独立责任方证明定点错误会红。本轮不新增规则门。

## 交接与停止点

交接强制引用本机制、功能矩阵、本轮原字节备份、peer 快照、变更文件、分门验证与未验项。待对齐工作不冒称已完成业务启用。清晰、低风险且已授权的本地修改继续执行；只在缺失权限、不可逆/破坏性动作或会实质改变范围时提出具体问题，不反复询问已有授权。
