### 0.2 开工前必须记录的机器画像

在目标机上开一个 PowerShell(普通权限即可),把下面几项抄进验收记录:

```powershell
# 系统
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
  Select-Object CurrentBuildNumber, UBR, DisplayVersion, EditionID, ProductName
# 架构与内存
$env:PROCESSOR_ARCHITECTURE
(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB
# 磁盘
Get-PSDrive -PSProvider FileSystem | Select-Object Name, @{n='FreeGB';e={[math]::Round($_.Free/1GB,1)}}
# 杀软 / EDR(有什么就记什么)
Get-CimInstance -Namespace root\SecurityCenter2 -ClassName AntiVirusProduct |
  Select-Object displayName, productState
Get-Service | Where-Object { $_.DisplayName -match 'Defender|CrowdStrike|SentinelOne|Carbon|奇安信|火绒|360|深信服' } |
  Select-Object Name, DisplayName, Status
```

<sub>检测命令出处:03 §2.15 速查表。杀软/EDR 一项是记录用,规格未定义具体判据。</sub>

**还要记**(后面每条判据都要拿它当基线)<sub>03 §8b 通用约定①②</sub>:

### 0.3 🔴 强烈建议:先做系统还原点或整盘镜像

**本手册会让这台机器发生整机级改动**(换 WSL 内核、启用 Windows 功能、装服务),其中"启用 Windows 可选功能"这一项**卸载时不会回退**<sub>03 §2.14 第 6 步"不禁用 Windows 功能"</sub>。所以:

- 能做**整盘镜像**(如 Macrium / Veeam Agent)最好;
- 退一步做**系统还原点**:`Checkpoint-Computer -Description "QTrade-fieldtest-before"`(需管理员);
- 目标机上**不要放任何你舍不得丢的数据**,尤其是别人在用的 WSL 发行版与 Docker Desktop 容器。

<sub>还原点/镜像本身是操作建议,规格未定义;规格只定义了"卸载还原清单"(§0.4)。</sub>

### 1.2 拷到目标机后先算哈希

```powershell
Get-FileHash -Algorithm SHA256 'D:\QTrade-Setup-1.0.0.exe'
(Get-Item 'D:\QTrade-Setup-1.0.0.exe').Length
```

**通过判据**:`Hash` 与 §1.1 **逐字相等(不分大小写)**,`Length` = 2259695672。
**不相等就停**——拷贝过程中损坏,重新拷,不要装。<sub>03 §2.2.1:sha256 不一致即 `PAYLOAD_CORRUPT`</sub>

### 1.3 会看到哪些拦截、怎么放行

这一版是**自签名**:在按 §1.4 导入证书之前,目标机对它的态度与未签名包相同;导入之后 UAC 预期不再显示「未知」,但 SmartScreen 仍可能照弹(见 §1.4.1)。所以目标机上预期会出现下面两类拦截 <sub>03 §2.2.3、installer/build/README §5</sub>:

| 现象 | 长什么样 | 怎么放行 |
|---|---|---|
| **SmartScreen** | 蓝底窗口「**Windows 已保护你的电脑**」,只有一个【不运行】按钮 | 点窗口里的「**更多信息**」→ 出现【**仍要运行**】→ 点它 |
| **UAC** | 「你要允许此应用对你的设备进行更改吗?」,发布者显示「**未知**」(未导入证书时;导入后显示什么照实记进 I-4) | 点【是】。🔴 **必须用当前登录的管理员账号点"是"**,不要在这里输入另一个管理员的账号密码——那会被安装器判 `ELEVATED_AS_OTHER_USER` 退 **23** <sub>03 §2.4.1</sub> |
| **EDR / AppLocker**(若目标机有) | 静默拦截、双击无反应,或 EDR 弹"已阻止" | 记录 EDR 名称与拦截日志,**不要关 EDR**,把现象写进验收记录并停止本次验收 <sub>03 §2.2.3:未签名 EXE 在企业机上大概率被拦,签名不是可选项</sub> |

> 自编存根内嵌了清单声明 `requireAdministrator`,所以**双击就会弹 UAC**;如果它没弹 UAC 就直接退出,那是异常,记录下来。<sub>03 §2.1 补丁(4)</sub>

#### 1.4.3 🔴 指纹另路核对(导入前必做)

1. 指纹必须经**与文件不同的渠道**拿到:口头告知,或另一条消息(不能跟 `.cer` 在同一个压缩包 / 同一封邮件的附件里)。
2. 导入前**肉眼逐字比对**:另路拿到的指纹 = 本节 1.4.1 表里的 `E36AFD96A801DD666F953AC8E3B3C992AB8CD60E` = 导入脚本打印出来的「指纹」行。
3. **三者有任何一处对不上就停**,不导入、不装,找安琳。

> 为什么不是形式:导进 `Root` 等于告诉这台机器「这张证书签什么都可信」,`.cer` 被人掉包就是一条后门。<sub>installer/build/README §5.4、`Import-QtCodeSigningCert.ps1` 头注</sub>

#### 1.4.4 导入(管理员)

**方式 A · 双击**:双击 `导入QTrade签名证书.cmd` → 弹 UAC 点【是】→ 窗口打印证书的**主题 / 颁发者 / 指纹 / 有效期** → 按 1.4.3 比对 → 提示「输入证书指纹以确认」时**手工输入**另路拿到的指纹回车(直接回车 = 取消,什么都不做)。

**方式 B · 管理员 PowerShell**(推荐,指纹由命令行给定,脚本逐字核对):

```powershell
# 以管理员身份开 PowerShell
cd D:\QTrade-signing
# 这几个脚本在目标机上还没被信任,只对本进程放开执行策略(关窗即失效)
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# 先干跑:只打印打算做什么,不导入
.\Import-QtCodeSigningCert.ps1 -CerPath .\QTrade-CodeSigning-E36AFD96A801DD666F953AC8E3B3C992AB8CD60E.cer -ExpectedThumbprint E36AFD96A801DD666F953AC8E3B3C992AB8CD60E -WhatIf

# 真导入
.\Import-QtCodeSigningCert.ps1 -CerPath .\QTrade-CodeSigning-E36AFD96A801DD666F953AC8E3B3C992AB8CD60E.cer -ExpectedThumbprint E36AFD96A801DD666F953AC8E3B3C992AB8CD60E
```

<sub>参数名 `-CerPath` / `-ExpectedThumbprint` / `-WhatIf` 以 `installer\signing\Import-QtCodeSigningCert.ps1` 的 `param()` 为准;`-ExecutionPolicy Bypass` 的理由见 `导入QTrade签名证书.cmd` 注释「证书还没导入,ps1 在 AllSigned 机器上本来就跑不了」</sub>

**它改动这台机器上的什么**(两处都是**全机生效**,别的什么都不改;已有就跳过,幂等):

| 改了什么 | 位置 | 为什么要 |
|---|---|---|
| +1 张证书 | `Cert:\LocalMachine\Root` | 自签名证书自己就是根;不导这里,验签恒 `UnknownError` |

### 4.4 怎么回滚内核

**三条路,按手边有什么选**:

1. **安装期失败页**:直接点【**回滚内核**】按钮(它走的就是自动回滚那段逻辑)。<sub>03 §2.6.4 第 8 步、§8b M0-6</sub>
2. **装完之后**:控制台 `P-ENV` 页的【**回滚内核**】(`qt-env-kernel-rollback`);还有【重新应用内核】。<sub>03 §2.6.5、§5.2</sub>
3. **手工兜底**(WSL 已经起不来时也能做,因为 `.wslconfig` 是 Windows 侧文件):
   ```powershell
   notepad "$env:USERPROFILE\.wslconfig"     # 删掉那一行 kernel=C:\\ProgramData\\QTrade\\kernel\\bzImage-6.6
   wsl.exe --shutdown                         # 🔴 这会中断 WSL 里所有程序,先保存
   wsl.exe -l -v                              # 确认发行版还在
   ```
   <sub>03 §2.6.5 第 3 步给的就是这套手工步骤</sub>

### 4.5 紧急恢复 WSL(退出码 65 之后)

1. 打开 `%USERPROFILE%\.wslconfig`,**确认里面已经没有 `kernel=` 行**(回滚失败时文件通常已经是这个状态了)。
2. **重启电脑**。
3. 重启后 `wsl.exe -d <你原有的发行版> --exec uname -r` 应该回到**官方内核版本串**。
4. 还不行:把 `%ProgramData%\QTrade\wsl\.wslconfig.bak-*` 里**最早那一份**(= 你原始的配置)手工拷回 `%USERPROFILE%\.wslconfig`,再重启。
5. 收诊断包报障,**不要**继续重试安装。

<sub>03 §2.6.5 第 3 步、§2.6.2 R1(备份永不覆盖旧备份,所以最早那份就是原始配置)</sub>

### 4.6 彻底不玩了:怎么卸干净

```powershell
& "$env:ProgramData\QTrade\install\engine\qtrade-setup-engine.exe" /QT_MODE=uninstall /QT_KEEP_DATA=0
```

卸完对照 §0.4 的清单逐项检查;其中 **1(Windows 功能)、2(WSL MSI)、14(VC 运行库)、15(微信版本)、16(微信备份目录)** 这五项**本来就不还原**,不是缺陷。<sub>03 §2.14-6</sub>
真要恢复到"动手之前"的样子,用 §0.3 的系统还原点或整盘镜像。

### 4.7 报障时请带上

1. `collect-evidence.ps1` 生成的 zip(桌面);
2. `%ProgramData%\QTrade\logs\diag-<ts>.zip`(如果有);
3. 退出码 + `install_state.json` 里的 `state` / `parked`;
4. 失败页的**截图**(文案里常带差额数字与话术);

6. §1.4.5 的验签输出:`Status` / 签名者 `Thumbprint`(须为 `E36AFD96A801DD666F953AC8E3B3C992AB8CD60E`)/ `Subject`,以及两个证书存储的 `Test-Path` 结果。

🔴 **发出去之前自己扫一眼**:包里不该有密码、令牌、微信聊天内容、`vault\` 下的任何东西。<sub>03 §5.3、§6 红线 2</sub>
