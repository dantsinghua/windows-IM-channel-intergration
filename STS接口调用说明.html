GET /api/sts

获取阿里云临时凭证。本地默认地址：http://127.0.0.1:8080/api/sts

请求

GET /api/sts

请求头必填说明
access_token 是 SM4-CBC 加密后的 Base64 字符串，约 1 分钟内有效 
curl -s http://127.0.0.1:8080/api/sts \
  -H "access_token: <按下方规则生成的 Base64>"

成功响应

HTTP 200，响应头带 Cache-Control: no-store。

{
  "access_key_id": "STS.xxx",
  "access_key_secret": "xxx",
  "security_token": "xxx",
  "expiration": "2026-10-12T10:08:50Z",
  "bucket": "yingmi-dev-its-test"
}
字段说明
access_key_id临时 AccessKey ID
access_key_secret临时 AccessKey Secret
security_token安全令牌
expiration失效时间，UTC，RFC3339。08:12:10Z 即北京时间 16:12:10
bucket配置项 aliyun.bucket

凭证缓存在服务进程内存中。距离 expiration 超过 5 分钟时，重复请求返回同一份凭证；进入最后 5 分钟或已经过期时，下一次请求会向阿里云重新申请。

失败响应

{"message":"错误说明"}
HTTP 状态message原因
401缺少 access_token没有这个请求头，或值为空
401access_token 无效Base64、解密或 JSON 格式不对
401key 不匹配原文里的 key 与配置 auth.key 不一致
401access_token 已过期ts 与服务器时间相差超过 60 秒
502具体失败原因校验已通过，但向阿里云申请 STS 失败

access_token 生成

配置在服务的 config.yaml：

auth:
  key: "定制的业务字符串"
  sm4_key: "16字节的SM4密钥"

auth.sm4_key 必须正好 16 字节。auth.key 是业务口令，和 SM4 密钥不是同一个值。

原文

{"key":"定制的业务字符串","ts":"1760260320"}
字段类型说明
key字符串必须与 auth.key 完全一致
ts字符串Unix 时间戳，单位秒。不要用毫秒，也不能写成数字

字段顺序和空格不影响校验。

加密步骤

  1. 用 auth.sm4_key 的 16 字节作为 SM4 密钥。
  2. 随机生成 16 字节 IV。
  3. 对原文 UTF-8 字节做 PKCS7 填充，分组长度 16。
  4. 使用 SM4-CBC 加密。
  5. 拼接 IV + 密文。
  6. 对拼接结果做标准 Base64（带 = 填充），放入请求头 access_token。

服务解密后检查：key 与 auth.key 一致；ts 与服务器当前 Unix 秒的差值绝对值不超过 60。同一条 access_token 不能长期复用。
