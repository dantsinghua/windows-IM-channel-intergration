## 裁决中最重要的几条(实现前必须知道)
1. **微信每个 wxid 一个独立 `wxNN`**,不是固定 `wx01` 换人;「一机一个在线」靠资源池槽位 `holder/pending`,没有 `switching` 状态。
2. **WinAgent = 服务 + 用户会话代理**两进程;对外只有服务监听 17610;`wsl.exe` 与微信 UI 自动化都在会话代理里 ⇒ 用户未登录 Windows 时 WSL/Agent 不自动起。
3. **调用方向恒 Agent → WinAgent**,WinAgent 从不回调;控制台监控/探测一律经 Agent。
4. **令牌只在 Vault**,经命名管道签发给控制台主进程,渲染进程零秘密;WSL 侧唯一落盘明文是 `/etc/qtrade/winagent.token`。
5. **画面流经 Agent 17600 WS**,不直连 scrcpy 端口;二维码/验证提示/倒计时一律走 `account_state.prompt`。
6. 微信取钥失败 = 读写都不可用;锁屏 = `degraded(SCREEN_LOCKED)`。
7. 表结构唯一出处:邮件三表 06、健康/探测表 04、安装状态/微信矩阵 03、微信档案 05,02 据此重做 DDL。
8. **除语音转文字 ASR 外全程序不用大模型**(A-1);截图读取走**离线 OCR**,编排是固定工作流。
9. **本地数据只留 30 天,采集侧文件 7 天**(E-18);磁盘三级水位 5/2/1 GB 硬保护,清理是保证不是尽力;**任何写入失败第一诊断是磁盘满**(`DISK_FULL`)。
10. **独立资源监控页 `P-RES`**(E-19):整机硬件 vs 本程序占用两栏并排,内存/CPU/磁盘三类都上盘;内存吃紧**只按 LRU 建议停用、不自动停**用户账号。
11. **容器停止即清可再生缓存**(E-19),绝不动登录态与业务数据;崩溃路径由下次启动前预清理补做。
12. 微信重装**禁止静默卸载**(实测 `/S` 会清空聊天记录与登录态),走覆盖安装或交互卸载;hosts 只能拦 `dldir1.qq.com`/`dldir1v6.qq.com` 两个下载域名。
