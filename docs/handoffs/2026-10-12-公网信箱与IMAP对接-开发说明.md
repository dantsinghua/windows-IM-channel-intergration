# 公网信箱与 IMAP 对接 — 第一期开发说明（待审）

状态：待安琳审阅。开发规格在 `specs/014-nyoss-imap-phase1/`（`speckit.md`、`plan.md`、`tasks.md`、`frontend.md`）。尚未写入 `docs/00` 裁决表，不改现有邮件模板锁。

日期：2026-10-12

涉及系统：

- 个人工作台：本仓库 QTrade Agent（可连公网的采集端）
- 内网存款：`njcb-deposit-agent`（nanyin-deposit，现收信主路径）
- 内网询价：`xunjia-agent`（机器人监控页 `web/src/pages/Monitor.vue`）

公网中转：`nyoss.yingmi.com`（阿里云 OSS，私有桶）。内网只出站，不部署穿透，不开放入站端口。

## 1. 第一期同时做两件事

两条都进第一期，互为补充，不是二选一。

| 路径 | 作用 | 谁消费 |
|---|---|---|
| OSS 信箱 | 指令下发、回执、企点全量消息、QQ 收发、微信群消息的加密中转 | 存款、询价、工作台 |
| IMAP 邮件 | 工作台按现有兼容模板发信，存款用现有 fetcher 解析 | 只服务存款的微信群解析 |

询价的企点全量消息走 OSS，不改造成邮件。存款的微信群两条都能进：OSS 解密后写入现有入站表，或 IMAP 走现在的 `fetcher/wechat_mail.py`。同一条消息只进一条路径，用消息 ID 去重。

## 2. 网络

```
内网存款 / 询价
    │  HTTPS 出站：写指令、拉消息、拉回执、拉目录
    ▼
nyoss.yingmi.com（私有 OSS）
    ▲  HTTPS 出站：拉指令、写消息、写回执、写目录
    │
个人工作台
    │  企点 / QQ / 微信仍在本机收发
    │
    └── SMTP/IMAP：只把选中的微信群，按锁死模板发给存款已在收的邮箱
```

OSS 是拉取，不是推送，不做 WebSocket。轮询间隔第一期 5 秒。秒级通知（事件通知 + 轻量队列）不在第一期。

## 3. 账号怎么认

绑定和历史都用登录后的稳定号码，不用界面上可改的备注名。

- 工作台：机器编号
- 微信：wxid
- 企点：企点号（如 `3007378246`）
- QQ：QQ 号（如 `415011447`）
- 群：该通道的群原生 id
- 展示：登录昵称加上述号码。备注从 A 改成 B，绑定不变

工作台定期把目录写到 `wb/{工作台}/catalog.json`（密文）。存款和询价只能从这份目录里选，不能手填备注名。

## 4. OSS 对象

桶私有。对象体是 AES-GCM 密文。密钥按绑定分发，只放本机环境变量，不进 OSS、不进代码。存款和询价各用各的密钥。OSS 服务端加密只作第二层。

| 前缀 | 谁写 | 谁读 |
|---|---|---|
| `wb/{工作台}/catalog.json` | 工作台 | 存款、询价 |
| `wb/{工作台}/out/{消费者}/...` | 工作台 | 该消费者 |
| `wb/{工作台}/in/{消费者}/{指令号}.bin` | 该消费者 | 工作台 |
| `wb/{工作台}/ack/{指令号}.bin` | 工作台 | 下指令的一方 |

对象名只含工作台、通道、账号号、群号、序号，不含正文。生命周期先留 7 天。

指令字段：`cmd_id`、`workbench_id`、`channel`、`account_uid`、`op=send_text`、`session.kind`、`session.native_id`、`text`、`idempotency_key`。

消息字段：`event_id`、`workbench_id`、`channel`、`account_uid`、`account_nick`、`session`、`dir`、`sender`、`text`、`ts`、`ext_msg_id`。

工作台收到同一 `idempotency_key` 只执行一次。内网用序号水位去重。

## 5. 存款：微信群

配置三级，从目录选择：

1. 哪一台工作台
2. 该工作台上的哪一个微信号
3. 该微信号的哪些群

未选中的群不上传、不发信。私聊第一期不进存款。

发送：存款把加密指令写到该工作台的 `in/deposit/`。工作台用现有微信发送，再写回执。

接收两条并列：

- OSS：工作台把选中群的新消息加密写到 `out/deposit/`。存款拉取、解密，写成现有入站消息，后面的清洗和解析不动。
- IMAP：工作台对同一批群，用已锁定的 `ibquote-163-v1` 模板发到存款正在收的邮箱。存款 `fetcher/wechat_mail.py` 不改解析规则。

模板锁死，不把「图片类型」等字段做成可配。信息段顺序保持：

群聊、消息序号、昵称、消息时间、每日序号、消息 ID、消息类型、文本消息内容、图片/文件附件、图片类型（仅图片）、是否撤回。

主题仍是「微信群聊消息通知」这一套。正文写「图片类型:缩略图」的邮件，存款侧继续整封不读。工作台只有拿到原图或高清图才发；只有缩略图时不发这封。

同一 `ext_msg_id` 若 OSS 和邮件都到了，存款只入库一次。

## 6. 询价：企点全量进监控页

`Monitor.vue` 已有企点号、聊天流、`/api/im/links`、`/api/im/send`、`/api/monitor/chat`。第一期不新做页面。

配置一项：哪一台工作台的哪一个企点号。该号的全部消息进入监控页中栏，不先按债券过滤。对得上券的仍标债券；对不上的也显示。

监控页发送仍走现有输入框和红线闸。成交类词继续拦截。通过后改为写 OSS 指令，不再直连企点。工作台用现有企点发送执行，回执回到监控页。

询价不走 IMAP。

## 7. 工作台

不重写企点、QQ、微信的发送实现。新增信箱模块，做五件事：

1. 写账号与群目录（登录昵称 + 稳定号码）
2. 按绑定把新消息加密写到 `out/`
3. 拉 `in/` 指令，转成现有发送：账号 + 会话原生 id + 正文
4. 写 `ack/`
5. 按存款的微信群绑定，用锁定模板发 IMAP 邮件

QQ 使用同一条 OSS 指令：QQ 号 + 对端号码或群号 + 正文。

## 8. 第一期交付

1. 工作台：目录、加密指令、回执、消息上传、IMAP 发信（仅选中的微信群）
2. 询价：绑定一个企点号；监控页看到该号全部消息；能回一条并看到回执
3. 存款：绑定一台工作台、一个微信号、若干群；这些群经 OSS 或 IMAP 进入现有解析；能往选定群发一条并看到回执
4. QQ：同一指令格式，指定号码收发各一条

## 9. 第一期不做

- 内网入站端口、穿透、自建中转进程
- OSS 上的 WebSocket
- 事件通知和轻量队列（需要稳定 1 到 2 秒再单独立项）
- 改 `ibquote-163-v1` / `collector-v1` 的字段和顺序
- 存款接收微信私聊
- 询价改成邮件
- 用备注名当绑定键

## 10. 请审的点

1. 存款同一群是否允许 OSS 与 IMAP 同时开，只靠 `ext_msg_id` 去重；还是配置里二选一
2. IMAP 发信邮箱用工作台现有邮件路由，还是单独配一对只给存款的邮箱
3. 目录刷新间隔、指令轮询 5 秒、对象保留 7 天，是否按此定
4. 询价监控页对不上券的企点消息，是单独一条「未归券」流，还是混在现有聊天流里淡化显示
