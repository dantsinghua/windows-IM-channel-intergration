**对 03 §2.9.3 的直接影响**:
1. 第 3 步「静默卸载不会删聊天数据」的假设**不成立**——`/S` 会清空数据。要么维持「交互式卸载,引导手动点」(现稿),要么静默前先把 `<根>\xwechat_files` 与 `%APPDATA%\Tencent\xwechat` **整目录重命名/搬走**、装完再搬回(风险:`DeleteWeChatDir` 传入了 `BackupFiles`/`QQBrowser Plugin` 两个名字,推断是删除时的排除子目录,但搬走后再搬回是否被新版本识别为同一登录态未验证)。**建议**:不卸载,直接用安装器**覆盖安装**目标版本(4.x 安装目录按版本分子目录,覆盖装等价于降/升级)——但这条同样要等安装包到手实测。
2. 版本检测不要用卸载键 `DisplayVersion`(会陈旧),用 `Weixin.exe` 文件版本或安装目录下的版本子目录名。
3. 卸载键在 `WOW6432Node` 下;`HKCU\Software\Tencent\Weixin` 只有 `InstallPath` 与一个 DWORD `Version=4065598732(0xF2511D0C)`。

⇒ 结论不变且更精确:**注册表只在安装器写入时更新,应用内更新不刷新**。§2.9.1「不用 `DisplayVersion` 判版本」的口径正确,原因是「可能陈旧」而非「一定错」。

## C.3 wx_key 取钥实测(微信 4.1.12.26 + wx_key2.dll)

环境:`chatlog_alpha/lib/windows_x64/wx_key.dll` = `wx_key2.dll`(md5 `b54602dadcec92fca3e3e12953be67ed`),微信 4.1.12.26 已登录。

**① DLL 与版本适配:通过**(`chatlog.exe key --debug` 原样输出)
```
[DLL INFO] 检测到的微信版本: 4.1.12.26      ← 版本识别正确
[DLL INFO] 正在扫描目标函数...
[DLL INFO] 目标函数地址: 0x7ffa94e4bf4c      ← 特征扫描命中(偏移适配 OK)
[DLL SUCCESS] Hook安装成功，现在登录微信...  ← hook 安装成功
```
⇒ **`wx_key2.dll` 对 4.1.12.26 有效**,资源包记录(「4.1.12.26 用 wx_key2 成功」)得到复现。`wechat_version_matrix` 的 `4.1.12.26 / wx_key2.dll / verified / bundled` 行确认无误。

**② 🔴 两类密钥的触发条件不同(本次最重要的发现)**

| 密钥 | 用途 | 取法 | **触发条件** | 时间窗 |
|---|---|---|---|---|
| **数据库密钥** `data_key` | 解密 SQLite 消息库 | wx_key.dll **远程 hook** | **只在微信「登录」那一刻**被调用;**已登录状态下 hook 装上也永远等不到** | 单次运行**前 30 秒** |
| **图片密钥** `img_key` | 解密 `.dat` 图片 | 原生**内存扫描**(Dart 模式) | 微信进程内存里出现该密钥,即**打开过任意图片** | 单次运行**约 60 秒**并行扫描 |

实测证据:
- 14:49 / 14:51 两轮:微信停在「设置-关于微信」页 ⇒ `data_key` 超时失败;14:51:44 用户点开图片后 `通过字符串扫描找到图片密钥!(在检查了 4157 个候选后)` ⇒ **`img_key` 成功**。
- 14:55:09 起 hook,14:55:32 安琳**退出登录后重新登录**(⚠️**快捷登录、无扫码环节**)⇒ `通过 DLL 获取到数据库密钥` ⇒ **`data_key` 成功**。**证明快捷登录(免扫码)同样触发**,不必真的扫码。

**③ 🔴 chatlog 的落盘条件:两把密钥必须在同一次运行内都拿到**

14:55 那轮拿到了 `data_key` 却因同轮没拿到 `img_key`,收尾打 `WRN 30秒轮询结束，已获取数据库密钥，但未获取到图片密钥`,**整轮结果不落盘**——事后 `~/.chatlog/chatlog.json` 里 `data_key` 仍为空(`img_key` 是更早那轮存下的)。

⇒ **正确的取钥操作顺序**(写进 05 首登引导):
1. 先起 `chatlog.exe key` 把 hook 装上(**必须先于登录动作**);
2. 用户**先点开一张图片**(几秒即可拿到 `img_key`,把时间留给下一步);
3. 用户**退出登录 → 立刻重新登录**(快捷登录即可,须在该轮前 30 秒内完成)⇒ `data_key`;
4. 两者同轮命中才会写入 `~/.chatlog/chatlog.json`。

## C.4 对设计的影响(已回写各分册)

1. **03**:随包 = `weixin_4.1.12.26.exe`,manifest 固定 sha256 `58997cfe…`;校验只认 sha256,不认文件名/外层 VersionInfo;辨识方法 C.1 写进「随包件校验」。
2. **05(影响最大)**:微信首登/取钥引导必须是**固定三段顺序**——「先起 chatlog 装 hook」→「引导用户点开一张图片」→「引导用户退出并重新登录」;**不能假设「起了 chatlog 就能取钥」**;界面要明写这两个用户动作与 30 秒窗口;取钥失败的首要排查项从「换 DLL 版本」改为「**是不是没有重新登录**」(换 DLL 排第二)。
3. **04**:`H` 系健康项里微信取钥失败的归因补「hook 已装但未等到登录动作」这一类,与「DLL 版本不匹配」区分。
4. **02**:`wechat_profiles`/`wechat_version_matrix` 记录 `4.1.12.26 + wx_key2.dll = verified(runtime 复现)`;取钥流程的两步人工交互进 `WAIT_*` 状态码语义(见 05)。
