## 2. 冲突清单

### 2.A WinAgent 形态与调用面

**B-01 🔴 WinAgent 是一个服务还是"服务 + 用户会话代理"**
- 涉及:00 §2 拓扑;02 §2.1/§2.4/§3.6;03 §2.8/§9.2/§10.4;04 §2.1/§2.10/§2.7.1
- 03 说:必须拆两进程——`QTradeWinAgent` 服务(LocalSystem:vault/monitor/netprobe/防火墙)+ `qtrade-winagent-user.exe`(登录用户:wslctl/wechat),理由①WSL 发行版、`.wslconfig`、VM 都按 Windows 用户登记,Session 0 看到的是 SYSTEM 自己的 WSL;②pyweixin UI 自动化要交互桌面。
- 02 说:单一服务(LocalSystem,pywin32 服务壳),五模块全在服务内,`uvicorn` 监听 17610;启动第 2 步由 `WinAgent.wslctl` 以 `autostart=true` 拉起 `qtrade`(即服务进程跑 `wsl -d qtrade`)。
- 04 说:§2.10 "[SCM] WinAgent 启动(LocalSystem)… `wsl -d qtrade -- true` 拉起 VM";但 §2.7.1 又承认 WinAgent 要经 `WTSQueryUserToken` 才能找到安装用户的 `.wslconfig`,§2.5.1 承认 `ES_DISPLAY_REQUIRED` 必须在用户会话里发;§2.6.4 读用户级代理也要用户令牌。04 已经意识到"按用户"这个事实,但只对文件路径做了处理,没处理 `wsl.exe` 本身按用户这件事。
- 基线说:§2 WinAgent 是"Windows 服务(LocalSystem 或专用服务账号),开机自启",五职责全在服务内。
- 裁决建议:**采纳 03 的两进程形态,但 17610 与全部 30 个 `/wa/v1` 端点归服务,用户会话代理不对外监听**。服务收到 `/wsl/*`、`/wechat/*`、`/power/keepawake(display)` 请求时经本机命名管道转给用户会话代理执行并回传;会话代理不在(无人登录)时这几组端点返回 `503 NOT_READY` 并在 `/wa/v1/health` 里 `user_agent:false`。这样 02 的调用面、令牌、审计一字不改,03/04 的"按用户"事实也成立。一句理由:03 的两个事实是硬约束(SYSTEM 账号下 `wsl -d qtrade` 根本找不到用户名下的发行版,微信 UI 自动化在 Session 0 不可能),而 02 的 30 端点是稳定契约,拆进程不该改契约。
- 连带必须改写的口径(三处都没写):**Agent 不再是"开机自启"而是"用户登录后自启"**——VM 只能由登录用户的会话拉起。基线 §2 "控制台关掉,Agent 与 WinAgent 照常跑"仍成立(会话代理不是控制台),但"开机无人登录时 Agent 已在跑"不成立;04 §2.10 启动序列第一步应改为"用户登录 → 计划任务起会话代理 → 会话代理拉起 VM";04 H01 抑制窗口的起点也随之改为登录时刻。提权:服务代做写 ProgramData/防火墙/`sc`;会话代理不提权(03 §2.8 第 4 步已如此);内核回滚 = 会话代理写用户 `.wslconfig` + 用户确认后的 `wsl --shutdown`,不需要管理员。
- 03 §10.4 的替代方案(发行版注册到服务账号名下)**驳回**:WSL 在 Session 0 的可用性未验证,且微信仍需用户会话——拆是逃不掉的,就不必再引入第二个未验证前提。

**B-02 🔴 02 的"只有 Agent → WinAgent、WinAgent 从不回调 Agent"与 04 的六处反向调用**
- 涉及:02 §2.5 方向;04 §2.3 H01、§2.6.2、§2.7.3、§2.8.3、§2.11、§3.4(`POST /probe` 转发、`/wsl/restart` 内部调 drain、`/docker/proxy` 转发给 Agent)、§5 F-01
- 04 说:WinAgent 探 Agent `GET /api/v1/system/health`(H01 双路径);WinAgent 收到 `/wa/v1/probe` 后"再让 Agent 跑 WSL 侧";`/wsl/restart` 内部先调 Agent drain;`/docker/proxy` 转发给 Agent 写 `proxy.conf`;网络事件"通知 Agent";Agent 探测结果经 `PUT /wa/v1/probes` 回写 winagent.db(这条方向正确)。
- 02 说:单向,理由是 WinAgent 不需要持有 Agent 令牌;微信推型事件由 Agent 轮询。
- 基线说:§2 "Agent 是唯一 API 入口";未规定 WinAgent 能否调 Agent。
- 裁决建议:**维持 02 单向契约,只开一个例外:WinAgent 可调 Agent 的免鉴权 `GET /system/health`**(H01/`agent_from_windows` 需要,且它本来就免鉴权);其余五处按下表倒转:

| 04 的反向调用 | 改为 |
|---|---|
| WinAgent 收 `/wa/v1/probe` 后转发 WSL 侧给 Agent | 探测编排在 Agent:`POST /api/v1/system/probe` 分侧执行,Windows 侧调 `POST /wa/v1/netprobe/run`;安装期 03 也调 Agent 这个入口(见 B-13) |
| `/wa/v1/wsl/restart` 内部调 Agent drain | Agent 提供 `POST /api/v1/system/wsl-restart`:Agent 先自 drain,再调 WinAgent `POST /wa/v1/wsl/restart` 做 terminate/shutdown/拉起;响应丢失无所谓 |
| `/wa/v1/docker/proxy` 转发 Agent | 改为 Agent 端点 `POST /api/v1/system/docker-proxy {enable}`,代理串从 `GET /wa/v1/netprobe/net-state` 取 |
| 网络事件"通知 Agent" | Agent 60s 轮询 `net-state` + 拉 `/wa/v1/monitor/alerts`;唤醒/VPN 翻转 30s 内被下一轮拉到即可 |
| `agent_base_url` 由 WinAgent 维护并"通过 `/wa/v1/net` 告诉控制台" | 保留(控制台是拉方,不违反方向) |
- 一句理由:02 的单向是为了 WinAgent 不持 Agent 令牌,这个安全收益真实;而 04 的每一处反向都能用"Agent 拉 / Agent 编排"等价替换,代价只是 ≤60s 延迟。
- 附带:02 #60 `/system/health` "免鉴权仅 loopback"——H15/`agent_from_windows` 的第二路是 `<WSL IP>:17600`,不是 loopback;02 应把免鉴权范围放宽为"loopback ∪ WSL vEthernet 子网",否则 04 的双路径判定永远只能走 Bearer。

**B-03 🟡 WSL 侧发现 WinAgent 地址的方法**
- 涉及:02 §2.5 地址、#16 `/wa/v1/wsl/host-address`、§7.1 `[winagent] url`;04 §2.6.3
- 02 说:"`/etc/resolv.conf` nameserver 或 `ip route` default",镜像模式下 `127.0.0.1`,"04 负责识别并把地址写进 `agent.toml`";另设 #16 让 Agent 首次向 WinAgent 问地址。
- 04 说:`resolv.conf` **不可靠**(VPN 改 DNS;V1 对策会主动把 `generateResolvConf=false`),结论只用默认网关;备用 `/run/qtrade/host.json`(WinAgent 经 `wsl -d qtrade` 写进 tmpfs);Agent 运行期缓存、H02 失败时重发现;不写 `agent.toml`。
- 裁决建议:采纳 04(默认网关 + `host.json`),02 §2.5 改口、删 #16(Agent 要先知道地址才能调它,鸡生蛋)、`[winagent] url` 只保留为人工覆盖项。理由:地址每次 VM 启动都变,写进静态配置文件本身就错。

### 2.D 探测与健康

**B-10 🔴 `probe_results` 的 `trigger` 三套词汇、缺 `SKIPPED`、缺 `side/level_reached`**
- 涉及:02 §3.2 DDL;03 §3.3 `phase(precheck|selftest|runtime)`;04 §3.2、§2.11、§9.1
- 02 说:`trigger CHECK IN ('install','manual','schedule','agent')`;`result CHECK` 九值(无 `SKIPPED`);列 `endpoint`,无 `side`/`level_reached`/`host`/`port`。
- 03 说:要 `phase ∈ {precheck, selftest, runtime}`。
- 04 说:`trigger ∈ {install, boot, periodic, net_event, resume, manual, wizard}`;`side ∈ {windows, wsl, container}`;`level_reached ∈ {none,dns,tcp,tls,http,proto}`;`host/port` 一端口一行;`result` 加 `SKIPPED`(目标未配置 / 探测框架自身异常 / Agent 不可达时 WSL 侧未测)。
- 裁决建议:按 04 的列集改 02 DDL,`trigger` 定为一套:`install_precheck | install_selftest | boot | periodic | net_event | resume | manual | wizard`(03 的 `phase` 折进来;02 的 `schedule`→`periodic`、`agent` 不是触发原因删掉);`endpoint` 保留代替 `host/port`;`result CHECK` 加 `SKIPPED`。一句理由:三套词汇在 CHECK 约束下插入即报错,不合并根本跑不起来;`SKIPPED` 的必要性 04 F-24 说透了——探测框架自己的 bug 不能伪装成 `TCP_TIMEOUT`。
- 附带:04 说 `probe_results` 只在 `winagent.db` 一份、WSL 侧结果由 Agent 回写——02 §2.7 "两库不互相引用、Agent 经 `/wa/v1` 拿"与此不矛盾(Agent 是**推**结果不是读库),但 02 §3.6 **没有写入端点**,需加 `POST /wa/v1/netprobe/results`(仅 Agent 令牌)。

**B-11 🔴 `health_samples`:02 的宽表(`ts_ms` 主键、Windows 侧专用)装不下 04 的每容器/每进程行**
- 涉及:02 §3.2 DDL、§7.2 `[monitor] retention_days=30`、§2.7 两库边界;04 §2.2 采样表、§3.1、§9.6;00 §7.7
