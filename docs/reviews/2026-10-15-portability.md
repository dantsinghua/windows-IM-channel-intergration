## 目标与边界

目标机不需要预装 Python、Node、Git、开发虚拟环境或原开发电脑目录。Windows 功能仍受现有平台前提约束：Windows x64、系统版本、硬件虚拟化、内存/磁盘、管理员授权和企业安全策略。不满足条件时报告实际原因，不承诺绕过系统策略。

## 两种入口

正式安装入口：install/engine/launch-installed.ps1。根目录由文件所在位置推导；核对服务身份、交互用户 SID、凭据管道、WinAgent 健康、会话代理、Agent 和 Docker 就绪后才启动控制台。桌面快捷方式由目标机安装器生成，不复制开发电脑的快捷方式。

开发入口：scripts/local_e2e/Start-Local.ps1。开发配置是调用机的私有 JSON，默认 LOCALAPPDATA/QTrade/development.json，也可显式指定 Context。开发构建需要工具链，此入口和配置不进入安装包；CheckOnly 只验证配置，不启动服务。配置记录目标发行版、工具和既有数据路径，代码中不固定开发用户名、盘符或历史构建目录。

## 实现约束

HTTP 普通请求保留 16 个受控名额，健康检查有独立且有界的保留容量；满载立即返回明确的过载错误，不无限排队。健康路径仍受请求体大小约束。

微信慢历史扫描保留有界内存检查点，后续调用继续；完整全局前缀确认之前不推进持久化游标。账号或取钥上下文变化使检查点失效。已验证的空集合 404 合同保留，其他 HTTP、网络、JSON 和数据形状错误分开报告。

SQLite 两份独立打包实现暂保留，新增 AST 一致性测试阻止单边漂移，不为节省 44 行代码引入跨安装包运行时依赖。MailConfig 实际被邮件测试使用，原审查将它列为未使用导入的判断已纠正，保留该导入。

正式总装检查 WinAgent Python 运行时、VC 运行库、Electron 资源、Chatlog/取钥库和离线 WSL 资产；关键 PE 必须为 x64。缺件、空文件、错误架构、开发路径或私有运行状态均阻止正式出包。控制台可执行名称显式固定为 QTrade.exe，与快捷方式一致。缺少构建工具必须非零退出，CheckOnly/SelfCheck 的非出包检查模式单独标识。
