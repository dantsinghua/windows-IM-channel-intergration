## 5. 缺口(三方都没定、实现必须定)

1. **`account_state` 事件的完整 payload 契约**——05 给了 `state_code/prompt/login_session_id`,01 期望 `enabled/runtime/capabilities/self_nick`,02 一个字段都没定义。需要 02 给一份合集(建议 = 05 §3.3 ∪ 01 §2.8 那行),并说明是全量 Account 快照还是增量。
2. **`alert` / `resource` / `mail` 事件 payload**——01 P-22/P-9 各提了一半,02 §2.2.7 只有 `emit(event, payload)` 签名。三个 payload 都要 02 定死(含 `alert.source` 用于跳页)。
3. **能力目录的 JSON Schema 来源**——01 P-2 要 `args_schema`,02 的 `adapters` 接口只有 `capabilities() -> set[str]`;谁维护每个 `op` 的参数 schema、放哪(代码常量 / `settings` / 文件),没人写。
4. **控制台令牌的生命周期**——01 说 `expires_at` 与 401 后重取,02 `api_clients` 无过期字段、无 `rotate` 对控制台行的说明,05 只说两把 WinAgent 令牌。需要定:控制台 Agent 令牌是否过期、谁轮换、轮换后 WinAgent Vault 如何同步(01 §2.3「Agent 轮换后 → WinAgent Vault 更新」这一步是 Agent 主动 PUT Vault?02 §2.5 说方向只有 Agent→WinAgent,可行但没写)。
5. **微信「新账号」登录会话的超时与取消**——05 给了 `login_session_id` 与 `qr_max_wait_s=1800`,但取消入口(`/wa/v1/wechat/login/cancel`)在 Agent 侧对应哪个端点、01 向导「取消」按钮调什么,没定。
6. **`state_code` 与 `state=error` 的关系**——05 把 `BOOT_TIMEOUT/BAD_CREDENTIAL…` 写成 `error(XXX)`,与 `login_required(WAIT_SMS)` 同一个字段?02 需定是同一列还是 `error_code` 另列;01 的对照表依赖这个决定。
7. **合规告知的真值**——01 存 `console.toml [setup] done`,02 用 `settings ui.consent_accepted_ms` 卡 `POST /accounts`,05 落 `audit_log` 并要求「文案改版重新勾选」。谁是真值、版本号比对在哪一侧做,三方都没闭合(A-17 给了建议)。
