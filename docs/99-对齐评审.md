## 2. 冲突清单

### 2.1 实体模型与拓扑

**C-01 🔴 微信账号 ID 模型三方不一致**
- 05 §2.4.2:每个 wxid 一个 `wxNN`,单在线用 `wechat_slots.holder/pending` 表达;`wechat_profiles.account_id` 与 `accounts` 一一对应(§3.1 提议 `UNIQUE`)。
- 01 §2.7.3「微信组」:「历史档案**不是 Account**(没有 account_id 也没有资源占用)」;§2.7.3.3 切换模式 = `POST /accounts/wx01/stop` 后 `POST /accounts {channel:'wechat'}` **新建**;§2.6.2「新增等于切换」。
- 02 §2.2.5 `can_add(wechat) = … count(wechat accounts, enabled) == 0`——只要存在一个启用的微信账号(哪怕 `stopped`)就不能再开,与 05「其余全是 stopped/disabled」的多 `wxNN` 直接冲突;§3.4.1 #2「微信已存在 409」;#13 `POST /accounts/switch {to_account_id}`(方向上支持多 id);§3.2 `wechat_profiles.account_id` 可 NULL 无 UNIQUE。
- 04 §2.5.3/§7.6 只用 `wechat_slots{used,max}`,无 `holder/pending`。06 §2.9 按 `account_id` 分账,天然要求每 wxid 独立 id。
- **裁决**:采用 05。理由:`session_id`/`messages.account_id`/幂等键全部挂在 `account_id` 上,共用一个 id 换人必串号;基线 §6「永不复用」正为此。02 改:`can_add(wechat) = wechat_enabled AND holder=='' AND pending==''`;#2 微信不再 409「已存在」而是「槽位被占 → 409 + 提示切换」;`wechat_profiles.account_id UNIQUE NOT NULL`。01 改:历史档案 = `channel=wechat` 且 `stopped` 的 Account 行,「切换到此账号」= `POST /accounts/{wxNN}/switch`,新账号 = `POST /accounts/switch {target:"new"}`;§2.6.2 表「多开」行改「≤1 在线,多档案」。04 §7.6 加 `holder/pending`。

**C-02 🔴 WinAgent 单服务 vs 服务+用户会话代理**
- 03 §2.8/§9.2:拆为 `QTradeWinAgent` 服务(LocalSystem:vault/monitor/netprobe/防火墙)+ `qtrade-winagent-user.exe` 用户会话代理(wslctl/wechat),理由:WSL 发行版与 `.wslconfig` 按 Windows 用户登记,Session 0 看到的是 SYSTEM 的 WSL;UI 自动化需交互桌面。
- 02 §2.4:单一服务 LocalSystem 承载五模块;§2.1 序 2 由服务 `wsl -d qtrade --exec /bin/true` 拉起发行版。04 §2.10 同(服务拉起 WSL);04 §2.6.4/§2.7.1 用 `WTSQueryUserToken` 去读用户级注册表与 profile——这只解决「读」,解决不了「以谁的身份跑 wsl.exe」。04 §2.5.1 承认 `ES_DISPLAY_REQUIRED` 在 Session 0 无效、要用户会话进程发,却把它交给控制台(可被关掉)。
- 01 §2.3:命名管道向 WinAgent 取令牌(不区分哪一半)。05 §2.2.1 机器级 DPAPI+熵(与拆分兼容)。
- **裁决**:采纳 03 的拆分——两条事实无法绕过(03 §2.8 已论证;04 自己的 `WTSQueryUserToken` 绕法只覆盖读)。归属:`17610` 与 `/wa/v1` 全部由**服务**监听;用户会话代理不对外监听,服务经本地命名管道调度它(02 新增内部 IPC 契约);`vault/monitor/netprobe/firewall/power(ES_SYSTEM_REQUIRED)` 归服务,`wslctl(wsl.exe 全部调用、.wslconfig 读写)/wechat(chatlog、pyweixin、讲述人)/ES_DISPLAY_REQUIRED` 归会话代理;`GET /wa/v1/health` 返回 `user_agent:true|false`(03 §2.11 已用),会话代理不在线时 wslctl/wechat 端点回 `503 NOT_READY`。02 §2.4 表加「执行体」列;04 §2.10 启动序列改「服务起 → 用户登录 → 会话代理起 → 会话代理拉起 WSL」——**这意味着用户未登录时 WSL/Agent 不会自动起来**,需明示(进 §5 待定 P-04)。

**C-03 🔴 WinAgent 回调 Agent 的方向被 04 多处违反**
- 02 §2.5「只有 Agent → WinAgent;WinAgent 从不回调 Agent」。
- 04 §3.4 `POST /wa/v1/wsl/restart`「内部先调 Agent drain」、`POST /wa/v1/docker/proxy`「转发给 Agent 写 proxy.conf」、§2.8.3「03 调 WinAgent `POST /wa/v1/probe`,WinAgent 再让 Agent 跑 WSL 侧」、§2.11「Agent 把结果经 `/wa/v1/probes PUT` 落 winagent.db」(这条方向正确)。04 §2.2 S12 `Agent 调 /wa/v1/time` 正确。
- **裁决**:维持 02 单向。改 04:①WSL 重启由 Agent 编排——控制台 → Agent `POST /api/v1/system/wsl-restart`(新)→ Agent 自 drain → Agent 调 `POST /wa/v1/wsl/restart`(WinAgent 只做 terminate/shutdown/拉起);②docker 代理由 Agent 端点 `POST /api/v1/system/docker-proxy {enable}` 承担,代理信息从 `GET /wa/v1/net` 拉;③安装期探测:Agent 可达时 03 调 Agent `POST /api/v1/system/probe`(Agent 再分侧调 WinAgent),Agent 不可达时才直调 `POST /wa/v1/probe` 且 WSL 侧记 `SKIPPED`(04 §2.11 末段的形态)。

**C-04 🔴 控制台令牌:凭据管理器 vs Vault,渲染进程能否见令牌**
- 01 §2.3:控制台不生成不持久化令牌,主进程经命名管道 `\\.\pipe\qtrade-winagent`(P-1)取,`webRequest` 注入,渲染进程永不见 `Authorization`。
- 02 §4 末段:「token 由安装器生成写入 **Windows 凭据管理器**与 `api_clients.secret_hash`;控制台主进程持有,**渲染进程经 IPC 拿到每次请求用的头**」——与 01 矛盾两处;同时 02 §3.6 又说控制台令牌是 `vault://winagent/console_token`(与凭据管理器矛盾)。05 §2.2.4 末:「`console` 令牌存 Windows 凭据管理器(主文档 §4.2)」。
- **裁决**:采 01。令牌只存 Vault(`vault://winagent/console_token`),经 P-1 管道签发给控制台主进程,渲染进程零秘密;主文档 §4.2「凭据管理器」在基线 v1.1 标记为被本条取代。02 §4 末段重写;05 §2.2.4 末改「Vault」。管道服务端在 WinAgent **服务**侧(C-02)。

**C-05 🟡 WSL 侧唯一落盘明文的例外条款**
- 基线 §11.1「WSL 侧永不落盘明文」。02 §2.5/§6/§9.10 与 05 §2.2.4 一致地把 `/etc/qtrade/winagent.token`(0600 root)作为唯一例外,理由都是鸡生蛋。
- **裁决**:采纳 02 §9.10,基线 §11.1 加「例外:Agent 调 WinAgent 的令牌 `/etc/qtrade/winagent.token`,0600 root,只能解锁 `/wa/v1`,轮换经安装器/修复模式重写」。两册措辞已一致,无需再改。

**C-06 🟡 微信 Vault/令牌条目命名与端点动词**
- 02 §3.6/§3.2:`vault://winagent/agent_token|console_token`,`vault_index.scope` 七类;`GET /wa/v1/vault/{name}` 读。
- 05 §2.2.2:`vault://api/token/console`,五类(无 `winagent`);§2.2.4:`POST /wa/v1/vault/{id}/read`、`HEAD`、`POST …/flag`。
- **裁决**:名字采 02(七类,`winagent/*`);动词采 05 的 `POST …/read`(读密文是副作用动作:记审计、计 `read_count`,不该是 GET),02 #4 改名;02 补 `HEAD` 与 `POST …/flag`;`vault_index` 补 `suspect/deleted_ms`(05 §9.10)。

### 2.4 事件、结果码、状态码

## 6. 总体评价

**01 控制台前端**——完成度高:11 个页面全覆盖、元素表 300+ 条、令牌交接与 Electron 加固论证扎实、23 条提议全部带理由。质量问题集中在**对 02/05 的假设**:微信档案不是 Account(C-01)、二维码 GET 轮询(C-12)、取钥失败仍可发(C-19)、`alert/mail` payload 自定(C-14/C-15)、十来个端点名与 02 不一致(C-40)。**最需要补**:按 C-45 补齐 04/05/06 要的元素(尤其 P-ACCT-DETAIL 的密码登录/立即重试/账号设置、P-SET 邮件密钥、P-ENV 内核回滚/防火墙修复),并把 §2.8 事件表改成消费 04/05/06 的 payload。

**02 后端与本地数据库**——31 张表 DDL、104 个端点、并发模型、恢复/停机、HMAC 规范都到了「能据此实现」的粒度,是六册里最完整的一本。问题是它先于其它册定稿,**对 04/06 的表只按自己理解写了一版**(C-26/C-31/C-37),对 05 的微信模型理解偏了(C-01 的 `can_add`),§4 末段令牌描述与 01 矛盾(C-04)。**最需要补**:按 C-21/C-26/C-31/C-36~38 重做 `messages/mail_*/health_samples/probe_results/install_state/wechat_*` 六组表,按 C-40/C-41 合并端点并加「执行体」列(C-02)。

**03 安装引导**——最贴近现有资产(逐条对应 `apply-binder-kernel.ps1`、`up.sh`、`.iss`),环境矩阵、可重入判据、回滚矩阵、退出码表完整,WSL 企业策略 `AllowCustomKernelUserSetting` 这类坑抓得准。两处越界:把安装器向导页写成 `P-SETUP`(C-39);WinAgent 拆分是正确的发现但需总控裁定(C-02)。**最需要补**:manifest 加 rootfs 内容清单(G-10/G-11)与 TZ(G-02);§7 段名对齐 04。

**04 系统监控与本地网络**——20 项健康检查、10 个探测目标、NAT 拓扑事实、VPN 五种冲突、adb server 5037 陷阱,专业度最高,红线守得最严。硬伤是**调用方向**:三处让 WinAgent 反向调 Agent(C-03),以及让控制台直连 165NN 取流(C-08),与自己 §2.1 第 2 条「汇总在 Agent」矛盾。**最需要补**:改 §2.8.3/§2.11/§3.4 三处方向;把 §2.5.1 的 keep-awake 结论喂回 05。

**05 账号配置**——三通道首登流程细到控件级,Vault 的 DPAPI 取舍、微信槽位模型、`degraded(KEY_FAIL)` 拒写、登出方式都有清晰理由,是本轮多个 🔴 裁决的「正确一方」。弱点:自造 testid(C-45)、`state_code` 枚举不全(C-17)、keep-awake 写了做不到的事(C-34)、自恢复判据与 02 不同(C-44)、`apk_url/boot_timeout` 与 02 重复定义(C-43)。**最需要补**:§2.0 枚举补全 + 记档微信窗口类名/更新包路径(G-07)。

**06 邮件摆渡与消息存取**——把 ibquote/collector 的真实行为(IDLE 坑、HTML 主路径、字节头识别、扩展块放标题行之前的理由)原样搬进来,模板字段与 HMAC 规范串可直接实现;清理算法「先归档后删、容量触发忽略保留期不忽略已处理」严密。问题:表字段与 02 分叉最大(C-26),`cursors`/`media`/`retention` 三处与 02 各说各的(C-23/C-24/C-43),微信轮询周期 120s 是从 collector 邮件场景照搬、与发送确认 10s 窗口不配(C-25)。**最需要补**:把 §3.1 改成「对 02 DDL 的 diff」而不是另一份全表,并删掉 `[wechat.poll]` 段。
