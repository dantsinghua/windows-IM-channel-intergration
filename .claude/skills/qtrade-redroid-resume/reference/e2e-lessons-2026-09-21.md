> 本文是**教训快照**,不是缺陷台账。下列问题**全部已修**(除标注外),留在这里是为了让下一棒知道**这些坑长什么样、为什么单测看不见、以后怎么防**。
> 原始证据在原机 `.omc/handoffs/`(git 忽略,不随仓库走):`e2e-rootfs.md`、`e2e-console-agent.md`、`e2e-recheck.md`、`payload.md`、`packager-2.md`、`winagent-impl.md`、`qidian-ui.md`。

## 一、跨部件接缝:两端各自全绿,合起来必断

### 1. 首启脚本调用了一个**不存在的命令行参数**(P0,阻断首装)

- **现象**:`installer/rootfs/files/qtrade-firstboot.sh` 调
  `/opt/qtrade/agent/venv/bin/python -m qtrade_agent.main --init-db --db /var/lib/qtrade/agent.db`,
  实测输出 `error: unrecognized arguments: --init-db`、退出码 2 ⇒ oneshot 失败 ⇒ 不 `systemctl enable --now qtrade-agent`、不写 `.imported`
  ⇒ 安装器的 `IMAGES_LOADED`/`DISTRO_IMPORTED` 判据全挂。**实物 wheel 与仓库源码表现一致**,不是推断。
- **为什么单测看不见**:Agent 侧单测测的是「跑起来之后」的行为,没有任何用例执行 `main.py` 的 argparse;
  rootfs 侧的 shell 脚本没有测试,两侧各自都"对"。**接缝上的字面契约(参数名)无人对账。**
- **怎么防**:①凡「A 部件的脚本调用 B 部件的 CLI」,把那一行**逐字**放进 B 的测试(或反过来,由端到端冒烟真跑一次);
  ②修复方式选了「给 `main()` 补 `--init-db` 分支(建库后 exit 0,幂等)」而不是删掉这一步——删掉会把首装竞争窗口放回来。
- 收口:commit `864db87`;裁决 R6-61(退出码 0/2/3/4/5)、R6-62(**调用方不得自加「库文件在就跳过 `--init-db`」的前置闸门**,否则升级/修复路径不跑迁移)。

### 2. 前端对着**自己写的 mock** 开发 = 自证(P0,控制台连真后端全线 426)

- **现象**(`e2e-console-agent.md` E-01~E-05):控制台写死 `X-QT-Api-Min: 1.3`,真后端 `api_version="1.0"` ⇒ **每个请求 426**;
  幂等键放在请求头 `X-Idempotency-Key`,后端只认 body 的 `idempotency_key`;
  HTTP 200 + `ok:false` 的**业务结果**被客户端当异常抛掉;`request()` 的「有 `data` 就返回 `data`」启发式把 `CommandResult` 拆了;
  WS 令牌无效时客户端只见 1006(规格是先 accept 再 close **4401**)⇒ 无限重连。另有 13 个端点后端缺实现、16 处形状不一致。
- **为什么单测看不见**:mock 是前端「**以为**」的后端,151 条前端单测全对着它跑,等于自己考自己。
- **怎么防**:①mock 必须对着**规格**而不是对着前端代码写,并加 `mock-shape` 自检把 mock 与真后端逐端点比形(现有 53 条);
  ②每批前端改动后,**用前端客户端源码直连真后端(全假件)跑业务线**,这是唯一能暴露此类问题的手段(跑法见 `.omc/handoffs/e2e-recheck.md` §7);
  ③真后端「无执行体」的端点**如实回 503/409 + reason**,不伪造数据——伪造会让联调假绿。
- 收口:commit `c6bc3e6`(控制台第一批)、`4d80ae3`/`c3e657b`/`85b02e1`(后端三批)、`dea4ae5`(控制台第二批)。

### 3. 企点 UI 执行层**根本没接线**

- **现象**:`adapters/qidian/ui.py` 写完了,但生产装配入口是 `sender=_sender_not_wired`——真机上按不了发送键。
- **为什么单测看不见**:测试一律注入假 `sender`/`login_fn`,**被测的从来不是生产装配那一行**。
- **怎么防**:凡「生产用真实现、测试用假实现」的注入点,补一条**只断言生产装配路径装的是真实现**的用例(不执行它)。
- 收口:commit `2accdcb`(真机 profile 仍待 `uiautomator dump` 后补,见 SKILL §5)。

## 二、构建与打包:不报错,但产物是坏的

### 4. 归档 > 2 GB 时,拼出来的 EXE 是「能双击、解压必炸」的残次品

- **现象**:`installer/build/build.ps1` 用 `[IO.File]::ReadAllBytes($part)` 拼三段;PowerShell 5.1 跑在 .NET Framework 上,
  `byte[]` 上限 2 GiB,而真载荷 `payload.7z` 2.05 GB 正好越线 ⇒ 最后一步抛「该文件太长」,
  但**存根与配置已经写进去了**,留下 ~209 KB 的残次品,外观与正常包无异。
- **为什么单测看不见**:Pester 用的是小样本;**只有真载荷才越线**。
- **怎么防**:改为 `OpenRead` + `CopyTo($fs, 1MB)` 流式拼接;出包后必做 `7z t`(须 `Everything is Ok`)+ 三段拼接算术核对(`Offset` = 存根 + 配置)。
- ⚠️ 连带:`docs/03` §2.2.2 估「rootfs 3.3 GB → LZMA2 后 ~1.5 GB」是错的——`docker save` 的镜像层**本身已 gzip**,LZMA2 再压几乎没收益(实测 rootfs.tar 2.16 GB 进归档仍 2.0 GB 出头)。**体积估算一律以实测为准。**
- 收口:commit `fbb38bd`。

### 5. `manifest.rootfs_contents` 恒为空 ⇒ 一道安全校验**静默失效**

- **现象**:`collect-payload.ps1` 写 `rootfs_contents = [ordered]@{}` 加一句「CI 在此登记」的注释,**但没有任何代码真去登记**。
  后果:安装期 `IMAGES_LOADED` 那步「按 `rootfs_contents` 复核 sha256/digest」什么都没校验——换过的 redroid 镜像、被替换的 adb 都能一路装完不报错。
- **为什么单测看不见**:**这个缺陷不会让任何构建报错**,两轮出包都「成功」过才被发现。空字典是合法值。
- **怎么防**:凡「校验用的清单」,加一条断言**清单非空且与来源逐字相等**(G-10);注释里写「CI 会做」的事,要么当场实现,要么让缺失变成 throw。
- 收口:同 `fbb38bd`(改为从 `<SourceRoot>\rootfs\out\contents.json` 原样读入,收了 `rootfs.tar` 却找不到清单时直接 throw)。

### 6. `setuptools` 的 `build/lib/` 增量缓存让**打包自检假绿**

- **现象**:给 `profiles/*.yaml` 补 `package-data` 后做反向验证(删掉声明),**居然照样全绿**——
  上一次拷进 `build/lib/` 的 `default.yaml` 还在,这次不声明也被直接复用。
- **为什么单测看不见**:测试自己就是在**被污染的源码树**里打的包。
- **怎么防**:①打包类测试的 fixture 先把 `pyproject.toml` + `src/` 复制到 **tmp 干净树**再打包;
  ②🔴 **正式出包前先 `rm -rf build/`**;③加**通用守卫**:`src/` 下任何非 `.py`/`.md` 的文件都必须出现在 wheel 里(以后新增数据文件忘了声明,这条先红)。
- 收口:commit `2accdcb` 的 `tests/test_packaging.py`(4 例)。

### 7. PowerShell 5.1 里 `| Out-Null` **吞掉原生命令的失败**

- **现象**:`winagent/build/build.ps1` 第 2 步 `pip install … | Out-Null`;PS 5.1 中**原生命令的非零退出码不触发** `$ErrorActionPreference='Stop'`,
  装依赖失败被静默吞掉,症状表现成第 3 步莫名其妙的 `No module named pytest`(真因还叠了「第 2 步漏装 `[dev]` extra」)。
- **怎么防**:构建脚本里每条原生命令后补 `if ($LASTEXITCODE -ne 0) { throw … }`(已抽成 `Invoke-Native`,commit `0dba42d`);
  验证「依赖装全了没」必须从**干净 venv** 开始(手工补装过的 `.venv-build` 会让它假绿,已删)。
- 另:同一脚本中文全乱码,因为文件**无 BOM**;PS 5.1 读脚本按 ANSI 解。

## 三、配置与可观测性:写了,但不生效 / 不可见

### 8. `StartLimitIntervalSec` 写在 `[Service]` 段被 systemd 忽略

- **现象**:`systemd-analyze verify` 输出 `Unknown key name 'StartLimitIntervalSec' in section 'Service', ignoring.`
  后果:Agent 进入「迁移失败拒绝启动」路径时不会被判 `failed`,而是被 `Restart=always` 无限重启刷 journal,`systemctl is-active` 永远是 `activating/auto-restart`。
- **为什么单测看不见**:单元文件没人 verify;**语法合法、键名不合法**。
- **怎么防**:单元文件改动后跑 `systemd-analyze verify`(零告警才算过)。
- 🔴 **本条尚未修复**(rootfs 重建批次的待办之一,见 SKILL §5)。

### 9. 健康检查**只改内存、不发告警**

- **现象**:`GET /system/health` 同一次响应里 `checks.H02/H03 = firing` 而 `alerts: []`——控制台、事件流、webhook 三处都收不到这两个 crit。
- **为什么单测看不见**:探针的单测断言的是**内存态翻转**,没有一条用例断言「翻转时必须产生 firing/resolve 事件」。
- **怎么防**:探针类用例的判据统一写成「**状态翻转 ⇒ 下游可见**」,而不是「状态变了」。
- 收口:commit `864db87`(登记 `H02_WINAGENT_API_DOWN`/`H03_DOCKERD_DOWN` 并在翻转时 firing/resolve)。

### 10. `--dev` 的「自包含」靠**平台巧合**成立,真机上往生产目录写

- **现象**:WinAgent `--dev` 一直靠「Linux 上 `%ProgramData%` 展不开 ⇒ 兜回 `--root`」这个巧合;
  真 Windows 上该变量展得开,于是 vault 熵文件、`kernel_dir`、`wsl_backup_dir` 三个写入落点逃出 `--root`,
  **跑一次 pytest 就在 `C:\ProgramData\QTrade\…` 留下 `FakeCrypto` 造的假熵、ACL 全开**。
- **为什么单测看不见**:测试**只在 Linux 上跑过**。在真 Windows 上跑同一套用例,一次就红。
- **怎么防**:①凡涉及路径展开/ACL/注册表的部件,**两个平台都跑同一套用例**(现已 Linux 与真 Windows 均 329 全绿);
  ②重基函数 `contain()` **不看平台、不看变量展不展得开**;③`--dev` 缺 `--root` 一律拒绝启动(不隐式落 `%TEMP%`);
  ④跑测前后都验 `C:\ProgramData\QTrade` **不存在**。
- 收口:commit `17dcb35`;反向验证:把 `place = contain if fake else expand` 抹成 `place = expand`,真 Windows 上该用例立即 FAILED 并报出逃逸路径。

### 11. 随包 Python 是 **3.11.0rc1**(候选版)

- **现象**:Dockerfile 直接 `apt-get install python3.11`,jammy 官方源给的就是 `3.11.0~rc1-1~22.04.1`。
- **为什么单测看不见**:它跑得起来、`pip check` 通过——**已知风险,不是已发故障**。
- **怎么防**:随包运行时的版本要**显式钉死并登记**,不靠发行版默认。
- 🔴 **本条尚未处置**(rootfs 重建批次待办)。

## 四、给下一棒的三条通用判据

1. **「四套单测全绿」只说明各部件内部自洽**;跨部件的字面契约(CLI 参数名、请求头名、键的位置、清单非空)必须由端到端跑一次真东西来证。
2. **构建不报错 ≠ 产物是好的**。出包后必须独立重算判据:`7z t` 完整性、`manifest` 四项(`lightweight=false`/`missing` 为空/`rootfs_contents` 逐字相等)、三段拼接算术、**包内装的到底是哪一份 exe**(比 sha256)。
3. **反向验证是唯一可信的自检**:每加一条守卫,就把被守的东西抹掉一次,确认它**真的会红**(本会话抓到过三条"首跑不红的空规则"、一次"被增量缓存掩盖的假绿")。
